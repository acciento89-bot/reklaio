# Reklaio per-remedy factual tracker

Architectural additive mobile subsystem under full human design autonomy; native inline no child agents. Fresh canonical acciento89-bot/reklaio main/audit pin929b4cc5d63fdaf788684f021cee2e27d1504791. Apple/Android de.kamilunavo.reklaio; source0.4.3(7), unchanged. Source identity is not proof of live binary provenance. Root owns all compilers/npm/tests/native devices/stores; worker never executes Node/npm/builds.

Novelty: full web source already has case-level provider responses/partial offers/tasks/escalations; do not duplicate those or claim they are absent. Mobile currently has synchronized cases/status/events/deadlines/documents and account/security/subscription. Choose per-requested-remedy actual fulfillment tracking, separate from offers, with partial remaining amounts/nonfinancial fulfillment, explicit local remaining actions, closed/reopened tracker history and a factual share preview. Modifying server case workflow would risk legacy data and notifications; a new local owner-scoped record is chosen. No backend writes, messages, email, AI/quota/subscription or statutory deadline behavior added.

Book bound to authenticated owner UUID + original case UUID. Requested remedies have stable local IDs, title, optional requested currency minor-units amount; nonfinancial remedies use explicit complete/incomplete. Offer/response notes never count as actual fulfillment. Progress entries record current received total (not additive double-counted payments), note, user-reported observed calendar date and actual recorded ISO time, plus optional existing document IDs. Updating/reducing total requires factual note and preserves previous entries; negative/over-requested/noninteger amounts reject. Latest progress observed date cannot move backward; late historical responses can be recorded without undoing current progress. All commands immutable, idempotent record IDs, monotonic book revisions and recorded times; changes on a closed tracker require explicit reopen. Titles/input lengths bounded; dates strictly real calendar days.

Remaining-action checklist distinct from existing server deadlines. Close requires at least one remedy, all remedies actually complete and all local actions done; retain closure snapshot and user note. Reopen preserves prior closure/notes. This closes ONLY the local tracker. Original case status, deadlines and configured reminders stay unchanged; report explicitly includes current original status and open deadlines. No legal conclusion or automatic entitlement/limitation period is inferred.

Separate version1 owner archive stores books; no old server schema/token/preferences/files changed. Immutable generation files plus a small SecureStore commit pointer: write new generation, verify bytes+schema+owner, then replace pointer, publish state only after commit. Corrupt/future/missing active generation blocks writes and preserves bytes; no silent reset/fallback. Serialize transactions per owner and reject stale same-book revisions to prevent lost updates. Namespace owner IDs strictly; no previous-owner UI state after auth switch. Account-deletion success additionally purges only that owner’s new local folder/pointer, blocks late queued resurrection, preserves original deletion/subscription behavior; actual cleanup failures produce an honest local-cleanup notice while logout/account deletion still complete. No actual account/backend write will be executed during this work.

Single shared React Native panel/screen under existing AppLockGate guarantees iOS/Android feature parity. New owner/case-bound component keys reset stale state; async results ignored after identity/unmount. Form fields retained on failed save/conflict and retry; no automatic overwriting with empty data. Case detail receives only the new tracker route/link; old case actions/attachments/timeline remain. DE/EN new module, native text share sheet from explicit preview only; no automatic sending and no originals attached. User notes quoted in deterministic report so embedded newlines cannot manufacture report sections. Missing/deleted document links shown as missing references, never fake attachment evidence.

Responsive new screen uses actual safe-area edges, keyboard avoidance, scrollable native controls, max content width driven by current window; no cached screen dimensions/manufactured hinge. Existing fixed tab-bar safe-area padding is a confirmed source adaptation candidate: use live inset for bottom height/padding while preserving layout. No broad old UI rewrite. Native lock, keyboard, short-height/window changes, input retention/share output and original workflows require root controlled native acceptance; source/typecheck/bundle is not Duo proof.
